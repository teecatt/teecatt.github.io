# MIDI 播放器 V2（重制版）

旧版听感不够好，但页面、玩法、谱面都已成熟——所以重制只做一件事：**把发声引擎换掉，其他全部原样保留**。
在线入口：门户 `MIDI播放器V2` 卡片。旧版 `../midi_player/` 已冻结，不再改动。

## 做法：克隆 + 换引擎

`index.html` / `app.js` 从旧版完整克隆过来，键盘、瀑布流、音游模式、变速、多 CDN、谱面逻辑逐行一致
（`app.js` 相对旧版 +229/−10 行，全是引擎相关）。中间其实走过弯路：第一版做了套全新独立 UI，
结果与现版差异太大被否决——用户要的是"同一个页面更好听"，不是一个新页面。于是推倒重来，回到克隆方案。

新引擎是 SpessaSynth（`vendor/` 下四个文件，Apache-2.0，LICENSE 随附），跑在 AudioWorklet 里，
音色库是自托管的 `GeneralUserGS.sf3`（8.4MB，和旧版走同一套 CDN 竞速 + Cache API，不重复下载）。
主链 `masterGain→limiter→analyser` 没动，复音上限 384。

## 音色为什么变好了

旧版是 55 个单采样 ogg 音色（FluidR3_GM）+ 简单的 attack/release 包络，说白了是"一个键一个录音"，
没有弯音、没有踏板、不认 CC 和 ProgramChange。V2 换成完整 SF2 合成后，
弯音（pitchWheel）、延音踏板（CC64，含单曲循环和停止时的复位）、力度与声像都由合成器表达，
听感差距主要就来自这里。上线前用 Node 做过离线渲染验证（287 个预设，Rush E 全曲渲染正常），
确认不是"响了就行"，而是"响得对"。

## 旧音色去哪了

55 个 ogg 音色在 V2 里已经没有入口（代码留着没删，防回滚），取而代之的是一套音色政策：
默认亮音钢琴（bank 就绪立刻切换，没就绪先拿合成钢琴顶着）；合成钢琴沉到底部"其它"分组；
原来"按谱面自动切音色"的逻辑整个删掉——切歌、删谱、上传都不再碰音色，音色也不进 localStorage。
谱面沿用旧版，另传了 5 首新谱（默认 `unchanged mind`）。

## 过程中修过的细节

- **按键没高亮**：SF2 的发声记在另一套表里，绘制循环读不到。加读 `_spessaActive`（含踏板挂起的音）解决。
- **下拉菜单每项重复**：`loadSongList` 多路并发交错，用代际守卫 `_songListGen` 挡掉过期回填。
- **整页放不出声**：V2 独立目录缺 `Midi.js`（相对路径 404，播放键全灰）。改成共享旧版 vendor，
  零重复下载，顺手把 bank 进度打进 console 并审计了全资源 HEAD 200。
- **和转写页联动**：`?from=transcribe` 时从同源 OPFS 读转写结果，经上传同一套路径入库并选中，音色政策照常。

## 已知的局限和下一步

V2 解析谱面时把多通道展平只读 ch0，所以多音色 MIDI 在这里按所选单音色发声——文件本身是标准的，
外部播放器/DAW 里是完整多音色。要在 V2 里按通道试听，得动发声主干（program/channel 透传 + 按通道踏板），
风险不小，另立项再做。另外 SF3 首载 8.4MB， topic 以后可以做分区加载。
